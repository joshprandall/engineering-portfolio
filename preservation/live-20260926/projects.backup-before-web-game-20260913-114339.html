ENGINEERING ARTIFACT / PYTHON

Recovery is a process.
Start with the evidence.

View source on GitHub ↗

The Recovery Readiness Auditor checks a declared service inventory for missing owners, overdue backups, stale restore tests, and incomplete recovery information.

Deliberately small

Python standard library. Local CSV input. Text or JSON output. No credentials, third-party dependencies, or network access.

Explicit assumptions

Checks recorded evidence against declared objectives. A clean report does not prove recoverability; restore exercises remain essential.

Testable behavior

13 automated tests cover time boundaries, timezone offsets, malformed input, missing fields, duplicate services, and CLI behavior.

EXAMPLE

Inspect the sample findings

Three fictional services · Audit time: September 6, 2026, 12:00 UTC+
  • Inventory API: no recorded gaps under the configured checks.
  • Reporting Database: backup older than its 4-hour RPO; restore test older than the 90-day policy.
  • File Services: missing accountable owner and recovery runbook reference.

Source code, fictional sample data, automated tests, design notes, and the CI workflow are available on GitHub.

ENGINEERING ARTIFACT / PYTHON

Dependencies become impact.
Make the chain visible.

View source on GitHub ↗

The Infrastructure Dependency Analyzer traces a declared service inventory to show potential downstream business impact, dependency paths, circular prerequisites, recovery-target alignment questions, and validation order.

Explainable impact

Reverse dependency traversal identifies potentially affected services and records deterministic shortest paths that explain why each result appears.

Recovery-aware modeling

Detects cycles, highlights RTO alignment questions, and separates declared recovery objectives from demonstrated recovery capability.

Tested behavior

25 automated tests cover graph directionality, cycles, duplicate paths, malformed inventories, safe report generation, and CLI behavior. GitHub Actions runs Python 3.10 through 3.13.

EXAMPLE

Inspect the fictional construction scenario

Business-impact analysis without live discovery or production data+
  • Office internet: traces six downstream services and three business workflows in the declared model.
  • ERP database: surfaces an 8-hour database RTO supporting a 4-hour application RTO as a planning review question.
  • Validation: dependency paths, prerequisite waves, owners, and cycles remain visible for review rather than being collapsed into a synthetic score.

Source code, fictional inventories, an interactive offline report, automated tests, and the CI workflow are available on GitHub.

ENGINEERING ARTIFACT / POWERSHELL

Lifecycle changes deserve a plan.
Make every action reviewable.

View source on GitHub ↗

The Employee Lifecycle Toolkit converts a declared directory snapshot, employee requests, and access policy into an explainable onboarding, role-change, or offboarding plan with projected state and request-level audit records.

Policy-first planning

Directory state, employee requests, and access policy remain separate inputs so decisions can be reviewed before any live integration or account change exists.

Guardrails by design

Approval gates, effective dates, identity consistency, protected accounts and groups, and managed-access scope are checked before actions are proposed.

Cross-platform tests

26 automated checks cover decisions, state preservation, repeat-run behavior, malformed input, and CLI output. GitHub Actions validates the suite on Ubuntu and Windows.

EXAMPLE

Inspect the lifecycle decisions

Fictional joiner, mover, leaver, scheduled, approval, and privileged-account cases+
  • Join: creates a projected disabled account, assigns the approved profile, and enables only after planned access is in place.
  • Move: reconciles managed groups while preserving access outside the toolkit’s declared scope for separate review.
  • Leave: plans disablement, session revocation, and managed-group removal while leaving retention, devices, applications, and ownership as explicit human follow-ups.

Source code, fictional policy and directory data, generated sample output, automated tests, and the CI workflow are available on GitHub.

The portfolio is part of the engineering.

View source on GitHub ↗

This site is a responsive static engineering portfolio built with semantic HTML, shared CSS, and plain JavaScript, with accessibility and progressive enhancement treated as design requirements rather than afterthoughts.

Static by design

No application server, database, API key, framework, or runtime dependency is required for the live site. Core content remains available before JavaScript runs.

Accessible interaction

Skip navigation, visible focus, keyboard-operable controls, native dialogs, project filters, reduced-motion support, and semantic landmarks are built into the interface.

Validated behavior

GitHub Actions checks required files, duplicate IDs, local references, skip-link targets, document language, external-link safety, project metadata, and core accessibility hooks.
