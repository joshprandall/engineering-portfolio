GUIDED LESSON / SOFTWARE RELIABILITY

Turn a production failure into a regression test

Prerequisite: Python functions and tests. Outcome: write an executable assertion for a defect, then verify the fix against the failing case and a nearby boundary.

Suppose a function grants access to a resource when its permission list contains a requested role. The bug is that a missing role list is treated as “allow.” A useful test records the input and required observable result: missing roles must deny. It should fail on the buggy implementation before the fix and pass afterwards.

Run this self-contained exercise

import unittest

def allowed(roles, required):
    # Replace this buggy rule after seeing the failing test.
    return roles is None or required in roles

class PermissionTests(unittest.TestCase):
    def test_missing_roles_deny(self):
        self.assertFalse(allowed(None, "editor"))

    def test_matching_role_allows(self):
        self.assertTrue(allowed(["reader", "editor"], "editor"))

    def test_other_role_denies(self):
        self.assertFalse(allowed(["reader"], "editor"))

if __name__ == "__main__":
    unittest.main()

Save as permissions_test.py and run python3 permissions_test.py. Expect the first test to fail on purpose. Change the return expression to roles is not None and required in roles, rerun, and inspect all three results. The test makes the requested behavior reviewable; it does not establish that an entire authorization system is secure.

Check the reasoning

The exact defect is the roles is None branch returning true. The corrected expression denies missing roles and any list without the required role, while preserving the matching-role case. A false positive test that merely asserts the function returned some Boolean would not catch the defect.

Common mistake: changing the implementation and then writing a test that can never fail under the old behavior. Reproduce the bug first and keep the regression in the suite. NIST’s SSDF also calls for tests covering previously reported vulnerabilities.

Limit: this tiny function ignores authentication, role provenance, revocation, concurrency and integration boundaries. A production check needs threat modeling, integration tests, and independent review.
