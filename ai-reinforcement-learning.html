What it is

Learn action policies from interaction, rewards, and state transitions while explicitly testing exploration, reward design, stability, and safety.

This page separates the concept, implementation path, interactive experiment, evaluation criteria, failure modes, and sources so the topic can be studied without relying on a summary tile.

Core concepts

  • A Markov decision process models states, actions, transitions, rewards, and discounting.
  • A policy maps observations or states to action probabilities.
  • Value functions estimate expected long-term return.
  • Exploration gathers information; exploitation uses what has already been learned.
  • Reward design defines what is optimized, not necessarily what a human intended.

Architecture / workflow

  1. Define environment state, allowed actions, reward, termination, and safety constraints.
  2. Start with a tabular or scripted baseline.
  3. Collect transitions and update a value function or policy.
  4. Evaluate on fixed seeds and unseen environment variations.
  5. Stress-test reward hacking, unsafe exploration, and distribution shift.

Technical foundations

  • Return Gₜ=Σₖγᵏrₜ₊ₖ₊₁.
  • Q-learning update: Q(s,a)←Q(s,a)+α[r+γmaxₐ′Q(s′,a′)−Q(s,a)].
  • Policy-gradient methods optimize expected return with gradients estimated from sampled trajectories.
  • Off-policy methods can learn from data generated by a different behavior policy.

Evaluation checklist

  • Average return with confidence intervals across seeds.
  • Success rate and constraint violations.
  • Sample efficiency and wall-clock training cost.
  • Robustness to changed dynamics, observations, and reward scales.
  • Behavior inspection, not reward alone, to detect shortcuts.

Failure modes and limits

  • Agents can exploit unintended reward loopholes.
  • Exploration can produce unsafe actions in real systems.
  • Results may be highly seed-sensitive.
  • Simulation policies may not transfer to physical systems without domain-gap testing.

Practical build path

  1. Implement tabular Q-learning in a small gridworld.
  2. Visualize Q-values and exploration rate.
  3. Change the reward structure and observe policy changes.
  4. Add constraints and compare reward-only optimization with safety-aware evaluation.
