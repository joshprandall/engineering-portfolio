What it is

Store, rank, retrieve, and cite relevant context so downstream reasoning can use external information without pretending retrieval itself guarantees correctness.

This page separates the concept, implementation path, interactive experiment, evaluation criteria, failure modes, and sources so the topic can be studied without relying on a summary tile.

Core concepts

  • Indexes organize stored items for lookup.
  • Sparse retrieval matches lexical terms; dense retrieval compares learned embeddings.
  • Reranking can apply a stronger model to a smaller candidate set.
  • Metadata filters constrain retrieval by source, date, permission, or document type.
  • Memory policy determines what is stored, refreshed, expired, or deleted.

Architecture / workflow

  1. Define the corpus, permissions, and freshness requirements.
  2. Build a baseline keyword index.
  3. Add embeddings and compare lexical, dense, and hybrid retrieval.
  4. Rerank top candidates and expose provenance to the user/model.
  5. Measure retrieval quality separately from answer quality.

Technical foundations

  • Cosine similarity: sim(a,b)=a·b/(||a||||b||).
  • Approximate nearest-neighbor indexes trade exactness for speed and memory efficiency.
  • Recall@k asks whether a relevant item appears in the top k.
  • RAG systems retrieve context before generation, but retrieved text still needs provenance and relevance checks.

Evaluation checklist

  • Recall@k, precision@k, MRR, or nDCG on labeled queries.
  • Freshness and permission correctness.
  • Latency at realistic corpus size.
  • Ablation of lexical vs dense vs hybrid retrieval.
  • Downstream factuality with and without retrieved context.

Failure modes and limits

  • Stale documents can outrank current ones.
  • Embedding similarity can return semantically related but task-irrelevant text.
  • Permission metadata can be lost if indexing and authorization are separated.
  • Retrieved misinformation can make generated answers more confidently wrong.

Practical build path

  1. Create a small cited document corpus.
  2. Implement keyword and cosine-similarity ranking.
  3. Add metadata filters and reranking.
  4. Evaluate retrieval against labeled questions before connecting it to generation.
