LEARN / CODING / FROM FIRST PRINCIPLES TO EXPERT SYSTEMS

Learn to code.
Then learn what the code is really doing.

This is a map of programming as a discipline: language fundamentals, data structures, algorithms, debugging, testing, APIs, databases, concurrency, operating systems, compilers, security, performance, distributed systems, graphics, embedded systems, AI, scientific/HPC work, hardware description, and quantum programming. The goal is transfer: understand concepts deeply enough that a new language becomes a syntax problem instead of a new way of thinking.

Scope note. No honest curriculum can contain every programming language, library, version, DSL, vendor API, and research prototype ever created. This atlas instead covers the major language families and the transferable skills underneath them, then links to primary documentation so a learner knows how to continue into any ecosystem.

01 / THE TRANSFERABLE CORE

What every programmer eventually has to understand.

Languages change. These ideas do not. Work through them in order, build something at every stage, and deliberately break your own programs so debugging becomes part of learning rather than a surprise at the end.

Computer + environment

Files, directories, paths, processes, terminals, editors, environment variables, packages, permissions, source control and how a program becomes a running process.

Build: command-line utility

Values + control flow

Variables, literals, types, operators, conditionals, loops, functions, scope, input/output and exceptions. Trace execution by hand before relying on a debugger.

Build: data transformer

Data structures

Arrays/lists, stacks, queues, hash maps, sets, trees, heaps and graphs. Learn the operation costs and the invariants each structure preserves.

Build: searchable index

Algorithms

Search, sort, recursion, traversal, dynamic programming, greedy reasoning, graph algorithms and numerical methods. Analyze time, space and failure cases.

Build: benchmark suite

Program design

Decomposition, modules, interfaces, cohesion/coupling, state, pure functions, dependency boundaries, error contracts and data modeling.

Build: multi-module app

Verification

Unit, integration, property, fuzz, end-to-end and performance tests; static analysis; code review; reproducible environments; CI; observability and rollback.

Build: tested release

Beginner

Write small programs without copying whole solutions. Explain every variable, branch and function. Learn Git early.

Intermediate

Use libraries deliberately, design modules, write tests, work with APIs and databases, profile code, and understand asynchronous/concurrent execution.

Advanced

Reason about memory, type systems, runtime behavior, distributed failure, security boundaries, numerical stability, build systems and performance.

Expert / research

Read specifications and papers; inspect generated machine code; prove invariants where warranted; design protocols, compilers or runtimes; reproduce benchmarks; state assumptions and uncertainty.

03 / PROGRAMMING PARADIGMS

The same problem can be represented in very different ways.

Procedural

State changes through ordered operations. Excellent for learning control flow and for systems with explicit steps.

Object-oriented

State and behavior are grouped behind interfaces. Learn encapsulation, composition, polymorphism and where inheritance creates coupling.

Functional

Prefer expressions, immutable data and functions. Learn higher-order functions, algebraic data types, recursion and effects.

Declarative

Describe the result or constraints rather than a step-by-step procedure. SQL, CSS and many configuration/query languages live here.

Event-driven / reactive

Programs respond to events and streams. Central to UIs, servers, games, sensors and distributed messaging.

Concurrent / actor

Multiple activities progress independently. Learn threads, async I/O, actors, message passing, synchronization, races and deadlocks.

Data-parallel / GPU

Apply operations across many elements simultaneously. Learn SIMD/SIMT, kernels, occupancy, memory hierarchy and transfer costs.

Logic / constraint

Declare facts, rules or constraints, then let a solver search. Useful for planning, verification, scheduling and symbolic systems.

Quantum circuit

Compose reversible/unitary operations, measurement and classical control while tracking amplitudes, phase, entanglement and hardware constraints.

04 / LOCAL CODE LAB

Change it, run it, explain it.

The JavaScript/HTML playground below runs inside a sandboxed iframe with a Content Security Policy that blocks network access. It cannot access the parent page. Use it for small experiments; serious work belongs in a real local project with tests and version control.

Practice loop

  1. Predict the output before running.
  2. Run once and compare.
  3. Change one assumption.
  4. Introduce a failure deliberately.
  5. Explain the failure in plain language.
  6. Add a check or test that prevents regression.

05 / COMPLEXITY LAB

Growth rate before stopwatch.

Big-O does not predict exact runtime, but it tells you how work scales. Use this model to see why an algorithm that feels fine at 100 items can collapse at a million.

Next: distinguish worst-case, amortized and expected complexity; then measure cache misses, allocations, I/O and parallel speedup on real hardware.

06 / DEBUGGING AS A SCIENCE

Turn “it does not work” into a falsifiable statement.

Rule: collect evidence before changing code. The fastest fix is often the one that proves which layer is actually failing.

08 / EXPERT LAYER

What separates “can code” from engineering depth.

Compilers & runtimes

Lexing/parsing, ASTs, IR, optimization, code generation, JIT/AOT, garbage collection, ABIs, linking/loading and language-server tooling.

Memory & concurrency models

Stacks/heaps, ownership, aliasing, atomics, memory ordering, locks, lock-free structures, async runtimes, schedulers and actors.

Distributed correctness

Partial failure, timeouts, retries, idempotency, consistency, consensus, replication, partitioning, clocks and observability.

Databases

Relational algebra, normalization, indexes, query planning, isolation, logs, replication, distributed transactions, document/key-value/graph models.

Secure software

Input boundaries, authentication/authorization, secrets, cryptography use, dependency trust, supply-chain provenance, sandboxing and abuse cases.

Performance engineering

Benchmark design, profilers, CPU caches, branches, vectorization, allocation, I/O, GPU memory, contention, queueing and capacity models.

Formal reasoning

Invariants, contracts, types, model checking, SAT/SMT, property testing, reproducibility and knowing when proof is worth the cost.

Numerical correctness

Floating point, conditioning, stability, error propagation, discretization, reproducible computation and validating models against known limits.
