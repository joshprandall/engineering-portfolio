AI DEVELOPMENT / FROM QUESTION TO EVIDENCE

One complete build: a measurable classifier

Start with a narrow question: can a two-feature model classify a synthetic observation? The included classifier study companion makes the entire path inspectable. Its 180 fictional rows use a fixed seed of 7. Split them into 100 training, 40 validation and 40 test rows before fitting the scaler or the logistic model. Fit normalization on the training rows only. Keep the test rows untouched until the procedure is frozen.

Run and challenge the result

  1. Download the executable study package. Unzip it, use Python 3.12, create a virtual environment, install the included requirements.txt, then run python -m unittest discover -p 'test_*.py'.
  2. Open notebooks/classifier.ipynb and run cells in order. Check the reported seed, split sizes, decreasing loss, baseline and 40-row confusion matrix against expected-results.json.
  3. Copy the data generator and increase noise for a new cohort. Freeze the original scaler and weights; record how many false positives and negatives change. A shifted cohort tests a new question and needs its own interpretation.

Video transcript: the AI development method

Define a specific task and identify the input, target and cost of failure. Start with a simple baseline. Split data before fitting; use training data to fit and validation data to choose. Freeze the procedure, then measure errors on held-out examples. Document limitations, require human review for consequential actions, and monitor changes after release.

Limits: This demonstration uses fictional generated observations and fixed parameters. Forty test cases do not quantify uncertainty for a different population; a lower training loss alone does not prove generalization. Before real use, specify the population and decision cost, obtain representative permitted data, test subgroup and shifted conditions, and define a rollback trigger.
